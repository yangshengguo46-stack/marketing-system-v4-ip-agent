# Video pipeline migration ledger

This ledger migrates reusable video-production capability into the Personal-IP
DeerFlow product without importing a second brain, database or lifecycle.

## Non-conflict architecture

- DeerFlow remains the only agent brain and tool runtime.
- `personal_ip_video_productions` remains the only production request and
  append-only event truth.
- The existing Video Workbench remains a projection of that ledger, never an
  authoring database or a second state machine.
- `faceless_material` is the Personal-IP material-video mode adapted from
  `marketing-os-desktop`.
- `generative_cinematic` is the short-drama, micro-film and advertising mode
  adapted from `video-studio` and executed with Seedream/Seedance.
- Provider/model selection is execution policy and receipt data, not workflow
  state.
- The customer-visible workbench has four stages only: setup, storyboard, edit
  and delivery. “Full auto” produces an editable rough cut.
- Shot chat, agent timeline commands and direct user edits resolve to the same
  typed edit operations and append-only timeline revision; a shot/clip id is
  an operation target, never conversation authority.
- Old repositories are read-only migration sources. Their uncommitted work is
  never edited, committed or copied wholesale.

## Explicitly excluded

| Source capability                             | Decision       | Reason                                                                                            |
| --------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------- |
| Hermes profiles, Kanban scheduler and leases  | do not migrate | DeerFlow already owns planning, delegation and recovery                                           |
| Video Studio WorkGraph/MediaFlow/crew runtime | do not migrate | It would create a second brain and lifecycle                                                      |
| Old project databases and UI-local state      | do not migrate | The current immutable request/event ledger is the product truth                                   |
| Duplicate model/provider router               | do not migrate | Providers are chosen by DeerFlow policy and recorded in receipts                                  |
| Blanket user approval for evidence/QA         | do not migrate | Routine validation is automatic; only high-risk publish/cost actions confirm                      |
| Account-bound conversation scope              | do not migrate | One conversation must coordinate the authenticated user's full portfolio                          |
| Vidi2.5/Vidi-Edit code or weights             | do not migrate | Published license is noncommercial; use only its chapter/highlight/edit architecture as reference |
| Shot2Story dataset annotations                | do not migrate | Dataset annotations are noncommercial even though the project code is open                        |
| Raw benchmark ASR/OCR as Skill instructions   | do not migrate | External content is evidence and may contain injection or copyrighted expression                  |

## Delivery order

1. Compile and seal plan, asset and storyboard contracts into the existing
   ledger.
2. Project those contracts in the current workbench.
3. Migrate the material-video rights, narration, frame-grounded selection and
   deterministic render path.
4. Migrate cinematic continuity, shot QA and exact approved assembly.
5. Add contextual shot conversation and one shared human/agent timeline
   revision contract; make both the compact dock and edit view adjustable.
6. Seal an intentional final edit before delivery QA.
7. Expand the accepted minimal one-shot cinematic run into one full multi-shot
   cinematic production and one real material-video production.
8. Run one real benchmark-video learning loop through MediaKit, the typed
   pattern compiler, `skill_manage`, a fresh production and measured
   retrospective. Add optional local model services only when their added
   coverage justifies shipping the weights.

Completion percentages must count this domain scope. A generic event, mock
provider or visually complete workbench is not counted as a completed
production capability.
