# 影视方法蒸馏器

把创作者名字从“风格标签”还原成能解决具体问题的方法。目标不是模仿某个人，而是回答：什么条件下，用什么机制，可能让观众产生什么体验，个人IP如何低成本验证。

## 与视频方法提取的边界

- 影片、剧集、主创、课程或多来源比较：在这里建立证据地图和机制卡；
- 用户给出一段长视频，要从时间证据编译出方法包：内部转到
  `video-method-distillation`；
- 两者结合时，先从视频保留时间码证据，再用本能力做跨来源核查、迁移边界和反例；
- 客户输出只给研究结果、依据和适用范围，不暴露内部能力名、路径或工具步骤。

## 工作流

1. 明确研究对象与使用场景。
   - 对象可为影片、主创、课程、题材或单一场景。
   - 场景至少写明平台、时长、真人/虚构、更新频率和可用资源。
   - 用户未提供IP信息时，先完成通用蒸馏，并把个性化部分标为待定。
2. 建立证据地图。
   - 优先顺序：创作者一手资料；电影机构与行业协会；同行评审研究；可靠报道；探索线索。
   - 查阅 `references/evidence-and-canon.md`。
   - 区分事实、跨来源综合、分析推断和创作假设。不要把成片分析冒充导演自述。
3. 分层拆解。
   - 故事：事件、人物、信息、情绪、世界。
   - 导演：场面调度、视点、空间、节奏、表演、声音。
   - 摄影：景别、焦段、机位、运动、光线、色彩、光学滤镜、机内Look与调色。
   - 编剧：欲望、阻力、选择、转折、揭示、代价、回收。
   - 制作：时间、预算、演员能力、场地和平台限制。
4. 生成“机制卡”，不要生成名人语录合集。
5. 做迁移与反迁移。
   - 迁移：保留功能，改写人物、语境、冲突来源与视听执行。
   - 反迁移：指出不适合手机竖屏、纪实真人、小团队或高频更新的部分。
6. 设计最小验证。
   - A/B只改一个主变量。
   - 同时记录叙事理解、目标情绪、看完率、评论复述和人物记忆。
   - 不用单次播放量替代机制验证。

## 机制卡格式

每张卡只处理一个问题，使用以下字段：

```markdown
### [机制名]
- 来源与证据级别：
- 证据性质：sourced_fact | cross_source_synthesis | analyst_inference | creative_hypothesis
- 要解决的问题：
- 触发条件：
- 必要输入：
- 机制：
- 成片中的可观察执行：
- 预期观众体验（概率性）：
- 失效条件：
- 个人IP转译：
- 最小测试：
```

## 创作者卡的使用边界

- 研究在世创作者时，提炼高层机制，不复刻其独特措辞、标志性桥段或可识别风格。
- 不以“红色=愤怒”“广角=压迫”之类固定词典解释镜头。视听意义由情境、表演、前后镜头与片内规则共同产生。
- 课程只总结公开可核实的结构与概念；未取得课程正文时，不猜术语定义。
- 资料有冲突时，列出冲突、来源时间和可信度，不偷偷选一个顺耳版本。

## 输出顺序

1. 一句话研究结论；
2. 证据地图与未知项；
3. 5–12张机制卡；
4. 适用与不适用条件；
5. 面向该IP的组合方案；
6. 一次低成本前向测试。
