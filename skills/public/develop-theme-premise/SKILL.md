# 主题与强前提开发

从真实矛盾出发，不从题材标签或人设口号出发。先读取 `$engineer-desire-behavior` 的生命周期欲望账本；没有主体、欲望、反欲望、成功/失败状态和可观察进度时，先补账本。强前提必须能持续迫使人物选择，同时允许现实产生意外。

## 工作流

1. 收集事实：人物、能力、欲望、义务、资源、边界、正在发生的变化。
2. 区分底层驱力、意识欲望、可见目标和当前策略；未知保持未知。
3. 找结构性矛盾：两个都合理但难以同时满足的欲望或需要。
4. 写主题问题，不先写答案。
5. 写正题与反题，让两边都能由具体人物辩护。
6. 生成3个强前提候选。
7. 对每个候选做12集压力测试和失败情境测试。
8. 选择最能让真实人物持续行动、又不要求造假的一个。

查阅 `references/premise-lab.md`。

## 强前提格式

`一个[具体人物]为了[可见目标]，必须反复在[稳定处境]中面对[反欲望/结构性矛盾]；他会用[可复发策略]行动，每次选择都会改变[关系/身份/能力]，观众长期追问[生命周期问题]。`

## 输出

- 事实素材与未知项；
- 主题问题、正题、反题；
- 3个强前提及取舍；
- 选定前提的事件生成器；
- 生命周期问题与终局条件；
- 观众情绪承诺；
- 真实性、伦理和可持续性风险。

不要把“做最真实的自己”“普通人逆袭”当主题；它们没有具体对立价值，也不能生成场景。
