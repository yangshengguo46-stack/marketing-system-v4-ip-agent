# 欲望—行为引擎

把欲望作为电影化个人IP的0号协议。先建立人物为何行动以及行动如何改变局势，再调用主题、人物、类型、情绪、情节、单集、表演或导演Skill。

## 核心链

```text
缺口/触发 → 欲望 → 可检验目标 → 行动策略 → 现实反馈
         → 策略变化 → 有代价的选择 → 状态改变 → 新欲望
```

欲望本身不是故事。只有当人物为它采取行动，并被反馈迫使改变策略或选择时，才形成可拍摄的故事。

## 工作流

1. 锁定欲望主体，不用“我们”“大家”掩盖谁在行动。
2. 分开四层：
   - `root_drive`：安全、依恋、自主、地位、照护、好奇等底层驱力；证据不足时写 `unknown`。
   - `conscious_want`：人物自己能表达的想要或逃避。
   - `goal`：在具体期限或触发条件下可判断成败的目标。
   - `tactic`：此刻为了改变人、物、关系或规则而采取的动作。
3. 找反作用场：
   - 另一个人的相反欲望；
   - 同一人物不能兼得的第二欲望；
   - 时间、信息、制度、身体、资源或世界规则；
   - 互相靠近、等待、观看或回应造成的变化，不强迫所有故事都有反派。
4. 把心理词改成动作动词：争取、隐瞒、试探、拖延、交换、修复、逃离、保护、揭露。
5. 写策略变化。重复同一动作只算升级，不自动构成转折。
6. 写有代价的选择和状态差值。结尾至少改变关系、身份、能力、信息、资源或世界规则之一。
7. 写观众欲望：观众为什么想继续确认结果、真相或选择。
8. 运行静音行为测试；不通过就回到目标和行动，不用旁白补洞。

详细字段、层级映射、情绪/类型转译与证据边界见 `references/desire-behavior-protocol.md`。

## 两份账本

### 生命周期欲望账本

回答这个IP长期追更的发动机：

- 主体持续想得到、保住、摆脱、隐藏或证明什么；
- 成功和失败分别是什么可观察状态；
- 哪些反欲望可以持续生成事件；
- 用什么现实证据记录进度；
- 哪些伦理边界不能为了冲突跨越。

### 单集欲望—行为映射

每集冻结：

- 主体、意识欲望和当集目标；
- 触发条件、反作用、得失；
- 策略序列和可拍行动；
- 有代价的选择、状态改变；
- 观众欲望与静音测试。

如已形成JSON，可运行：

```bash
python scripts/validate_desire_ledger.py path/to/desire.json
```

## “猴子测试”的使用边界

把它当作前语言因果可见性测试，不当作生物学定律：

- 静音去字幕后，能否看出谁想要什么；
- 能否看出他正在采取什么行动；
- 能否看出反作用和失败后果；
- 能否看出结尾状态已改变。

它只验证“看得懂”，不验证主题深度、伦理复杂性、潜台词或审美价值。原始欲望负责入场，矛盾欲望和代价负责留下。

## 下游交接

- `$develop-theme-premise`：读取不能兼得的欲望，生成主题问题和强前提。
- `$design-character-relations`：让每个关系人物拥有独立欲望，不把配角当阻碍道具。
- `$route-ip-genre-engine`：把类型定义为欲望面对特定信息、规则与代价的方式。
- `$shape-ip-emotion`：按欲望重要性、距离、变化速度、控制感和归因设计情绪。
- `$engineer-plot-information`：只组织由行动、反馈和选择造成的因果。
- `$write-ip-episode`：把当集欲望映射转成事件闭环。
- `$coach-ip-screen-performance`：把策略改写成演员可玩的行动。
- 导演与摄影：优先拍清目标对象、行动、反作用和状态差值。

## 输出

1. 已知事实、推断与未知；
2. 生命周期欲望账本；
3. 当集欲望—行为映射；
4. 欲望冲突图；
5. 行动—反馈—策略变化链；
6. 观众欲望；
7. 静音行为测试；
8. 下游Skill交接字段。

不得替真人宣称隐性欲望。未经证实的深层动机必须标为推断或未知；不得为了让故事成立制造冲突、羞辱或真实伤害。
