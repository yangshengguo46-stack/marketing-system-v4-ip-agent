# 真实IP素材入库

先保护现实，再组织故事。只处理用户授权范围内的材料，不把缺失信息补成戏。深层驱力证据不足时写 `unknown`，不得替真人下结论。

完整契约见 `references/project-data-contract.md`。

## 使用产品原生真相源

1. 先调用 `personal_ip_operating_cockpit`，再用
   `personal_ip_read_strategy_context` 读取当前主体的最新策略版本。复用已有事实，
   不从聊天内容重建一份平行档案。
2. 对新增材料做证据分级、同意检查和敏感性检查。长文本、原视频、截图与录音留在
   已授权的原始来源或产物中；策略版本只保存紧凑判断与不含凭证的证据引用。
3. 当材料足以改变人物证据、商业判断、边界、内容供给或公开表达时，调用
   `personal_ip_record_strategy` 追加一个不可变版本。使用稳定的
   `operation_key`；未变化的字段从上一版本继承。
4. 账号和平台只能是发布、采集、浏览器控制等具体操作的目标。人物、业务、定位、
   名称、受众和表达规则只能属于主体策略，不能复制进账号记录。
5. 素材多少不决定能否记录或创作。把本轮整理结果作为带来源的工作产物，明确
   未知项；策略阶段只是兼容标签，不是准入门槛。

不得创建 `project.json`、本地 JSONL 台账或另一套主体数据库。项目原生策略、
preflight、发布回执、指标和复盘服务是唯一运行状态。

## 材料整理格式

每条候选证据至少说明：

- 发生或观察时间；
- 来源类型与不含凭证的来源引用；
- 涉及人物、可观察行动和结果；
- 证据等级；
- `public/private/restricted` 隐私级别；
- `confirmed/not_required/unknown/withdrawn` 同意状态；
- 与当前判断的关系；
- 冲突证据和仍未知的部分。

可把文件哈希、平台观察ID、指标观察ID、发布回执ID、复盘ID或授权页面记录作为
`evidence_refs`，但不得把 Cookie、Token、密码、浏览器配置路径或大段私密原文写入
策略。

## 证据分级

- `sourced_fact`：文件或可核实记录直接支持；
- `testimony`：当事人陈述；
- `cross_source_synthesis`：多项材料综合；
- `analyst_inference`：研究者解释；
- `creative_hypothesis`：等待拍摄/数据检验；
- `unknown`：不知道。

不可把推断升级成事实。证据发生冲突时并列保存，不删除旧记录。

## 隐私与同意

`privacy` 使用 `public/private/restricted`；`consent` 使用 `confirmed/not_required/unknown/withdrawn`。`withdrawn` 证据不能进入新预写。

未成年人、客户、医疗、财务、住址、法律争议默认 `restricted`。不替用户决定公开。

## 入库后

1. 核对生命周期欲望：主体、底层驱力证据、意识欲望、成功/失败状态、反欲望、
   可观察进度和伦理边界；
2. 更新长期五线账本，但只把证据充分的长期判断写进主体策略；
3. 从研究库找机制，不找表面相似故事；
4. 把授权证据转成单集，保持事实与创作假设分离；
5. 发布前用项目原生 preflight 冻结欲望映射和盲预测。

真人纪录可以组织事件、压缩时间并说明不确定性，不能预写现实结果、伪造因果或强迫家人表演。
