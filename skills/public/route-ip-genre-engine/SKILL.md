# 个人IP类型发动机

类型不是滤镜，也不等于某一种情绪。类型是欲望进入特定信息、规则、空间与代价之后的变形场。没有欲望—行为账本时，先调用 `$engineer-desire-behavior`。

## 路由顺序

1. 先读取主体欲望、反欲望、成功/失败状态和现实资源。
2. 再写观众希望反复获得的体验。
3. 从 `references/genre-engines.md` 选择一个主发动机。
4. 最多选择两个辅助发动机，并说明各自只负责哪一层。
5. 生成连续12条不依赖热点的事件题目，检验能否持续。

## 类型合同

为每个主类型填写：

```markdown
- 核心观众问题：
- 主体欲望与反欲望：
- 类型如何改变欲望的实现条件：
- 信息分配：
- 反复冲突：
- 典型选择与代价：
- 情绪范围：
- 单集闭环：
- 长线积累：
- 必须兑现的承诺：
- 最容易滥用的表面符号：
```

## 混合类型规则

- 主类型决定单集主要满足；辅类型改变过程或余味。
- 混合必须共享同一人物选择，不能只是“前半搞笑、后半煽情”的拼接。
- 悬疑可负责信息，喜剧负责压力释放，家庭剧负责关系代价；三者仍须围绕同一个事件。
- 科幻在个人IP中优先作为“规则改变器”或思想实验，不默认依赖特效。
- 纪录/真人内容不能为了类型满足伪造关键事实；重演需披露。

## 选错类型的信号

- 只能描述美术与滤镜，说不出观众在追问什么。
- 连续三条都靠偶然、误会或陌生人配合。
- 主角不做选择，只被热点推着走。
- 换掉人物欲望后类型合同仍完全不变，说明只有表面符号。
- 每集情绪相同，没有压力与释放的变奏。
- 辅类型比主类型更有满足感，说明路由应重做。

## 输出

1. 主类型、辅类型与选择理由；
2. 类型合同；
3. 五条故事线分别由哪个发动机驱动；
4. 12个事件生成器；
5. 三个混合类型样集；
6. 类型漂移与伦理风险检查。

不要按平台标签替代类型设计。“剧情”“生活”“知识”是内容分类，不足以构成戏剧发动机。
