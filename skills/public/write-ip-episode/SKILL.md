# 个人IP单集编剧

单集先让当天没看过前文的人获得满足，再让追更者看见一点积累。写作时建立当前故事所需的最小欲望—行为链；不要要求用户先补一套表格，也不要用“这是长线伏笔”掩盖本集没有事件。

## 输入检查

收集或合理假定：

- 平台、时长、画幅和发布语境；
- 当日真实素材、可重拍程度和真实性边界；
- 主体的意识欲望、当集目标、触发、反作用、策略、选择和代价；
- 观众想确认的结果、真相或选择；
- 观众入场需要知道的信息；
- 本集允许推进的一个长期变量；
- 演员、场地、时间和道具。

## 写作流程

1. 明确人物欲望、目标、行动与反作用；复杂故事可读取 `$engineer-desire-behavior`，简单故事直接建立最小映射。
2. 写事件闭环：谁想在什么时候完成什么，采取什么策略，反馈如何迫使改变，最后发生了什么。
3. 写人物差值：开头与结尾在认知、关系、能力或身份上至少有一个可见微变化。
4. 决定信息视点：观众比人物多知道、少知道或同步知道。
5. 选择5–9个动作节拍。每个节拍必须造成新信息、反馈、策略变化、选择或兑现。
6. 写台词意图，再写台词。
   - 每句台词应在争取、遮掩、试探、攻击、安抚、拖延或转移。
   - 删除只向观众解释双方都知道的事实。
7. 设置钩子与回收。
   - 钩子承诺本集问题，不用虚假夸张。
   - 回收必须回答、完成、反转或有意识地延期，并给出延期的新证据。
8. 加入一处长期IP差值，通常不超过本集总信息的20%。

查阅 `references/episode-craft.md`。

## 输出

服从用户要的交付粒度。需要完整首条视频时，至少给出一句话故事、动作节拍、可说的逐字稿或场景稿，以及必要的拍摄提示；把欲望分析、传播设计和真实性说明融入同一份成稿，不机械拼接多份方法报告。

## 质量闸门

- 静音看画面，是否仍能识别主要行动？
- 静音时是否能识别谁想要什么、反作用、后果和状态变化？
- 去掉长期线，本集是否仍成立？
- 去掉本集，本季是否产生一个可记录的微小缺口？
- 转折是否来自人物选择或已埋条件，而不是作者突然安排？
- 结尾是否完成情绪，而不只是停止视频？
- 真实人物是否理解并同意关键呈现？

若用户只要求提纲，不自动扩写成逐字稿；若用户要求逐字稿，保持口语可说性，避免书面旁白淹没行动。
