# 编导因果联想方法 v3

本阶段只做语义路由，不写故事。目标不是把行业词逐层抽象，而是找到一个属于当前主体、
又能反复生成人物行动与关系变化的内容引擎。

## 先分开两个问题

- `content source`：每集真正讲什么人、什么关系、什么不能兼得的欲望；
- `subject ownership`：为什么由这个人讲、用这种语言或表演来讲才成立。

行业、产品、场地可以是内容来源，也可以只是主体归属或拍摄舞台。不要因为用户有某个阶段身份，
就让他永远只讲这个身份的直接邻域。

## 事实不能被推理改写

`facts_used` 逐字复制。假设字段可以发散创作，但不得把一条较弱事实改写成更强履历，再用
`fact_refs` 伪装成获得证明。经营一个地方不等于一直生活在那里；与某类人聊天不等于已获得
对方的完整经历、遗憾或智慧。所有超出原句的内容都只能作为待验证的创作假设。

## 近、中、远不是同一条抽象梯子

- `near`：内容来源与主体归属都来自行业事实；
- `mid`：行业中的动作、反馈或因果边被迁移到人的关系，行业作为隐喻来源；
- `far`：内容来源改为人的具体困境，职业、产品、场地及其日常直接相邻人物都不再提供选题。
  主体归属只由输入已有的观察、语言、表演、行动或人生经历承担；原行业最多保留为不发生因果的拍摄舞台。

中路要迁移“关系或因果边”，不是换一个感悟词。远路则不得继续依赖乡土、顾客、同行、家庭成员或
日常接触者作为便宜的内容源。删除原行业世界后，它应当能在一个完全无关的社会场景中重述，仍然保留
同一个人物欲望、行动反馈和关系变化。

## 先在内部做因果跃迁，再输出一条远路

不要把第一个安全联想当答案。在内部从不同的人类系统产生至少三个候选：不同的权力位置、亲密距离、身份表演、
利益交换、责任边界或自我欺骗结构。这些只是检索维度，不是可直接复用的选题。

每个候选必须回答：

1. 两个同样合理的欲望为何不能同时得到；
2. 人物做了什么可见动作，现实怎么反击；
3. 为什么现有事实能让当前主体用自己的方式演、讲或观察它；
4. 每集换人物和事件后，同一因果引擎能否继续生成新故事。

选择语义跨越最大、因果链仍连续、主体又真能承担的一项。输出的 `content_subject_hypothesis` 必须是可重复生产的
人物冲突机制，不是“生活、选择、成长、治愈”之类题材标签。

## 收敛

比较三路时分别判断：内容引擎是否具体；是否能反复生成事件；是否由当前主体的真实能力承担；是否适配生产限制；
内容之外是否有清楚归因。不要因为中路最安全就自动选它，也不要因为远路看起来高级就自动选它。

完成统一路线合同后立即停止，不写人物、剧情、脚本或运营建议。
