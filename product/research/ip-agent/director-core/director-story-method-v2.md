# 编导因果桥方法 v2

本阶段只把冻结路线编译成一句话故事，不重新发散、不换方向，也不把商业目标写进故事人物的
欲望。

## 信息边界

原始 `facts` 才是用户事实，`facts_used` 必须逐字复制；路线中的语义、受众和关系判断仍是创作假设。所有新人物、事件、
对白、经历和结果必须列入 `creative_assumptions`。不得把路线里的修辞压缩成主体真实履历。

## 有效因果，不是填满槽位

一个触发打破原状态；主人公为可判断成败的当集目标采取第一策略；现实给出具体反馈；主人公
据此换招；换招逼出当下真正不能同时选择的两条路径；主人公亲自支付一个可观察、并在场景结束
后仍然存在的代价；最后明确目标是达成、失败还是被改写，以及哪段关系或状态因此改变。

必须满足：

- `want` 是渴望的关系或状态，`goal` 是当集可判定的行动终点；
- `initial_tactic` 与 `strategy_change` 是不同动作，不是换种说法；
- `costly_choice` 的两个选项必须是当下可执行的不同路径，并在 `why_incompatible_now` 说明互斥；
  诚实与体面、爱与离开之类抽象词本身不构成选择；
- `cost.bearer_ref` 必须是主人公，`paid` 和 `persists_after_scene` 都要具体。让配角哭、沉默或离开
  不是主人公的代价；
- `goal_outcome` 必须明确目标达成、失败或被改写；`state_change` 要包含这个结果，不能用一个象征
  道具或“开始拍摄内容”代替人物世界的结果；
- 眼泪、遗物、重病、离别和突然死亡不能叠加充当廉价强度；优先用行动后果制造强度。

## 编译到真实生产条件

故事可以包含不出镜的虚构人物，但必须服从输入的拍摄条件。若只有一名出镜者，`actors` 和
`production_translation` 要明确谁是镜头内讲述者、谁只存在于口述或声音中；故事不得要求观众
实际看到第二名演员的表情、哭泣、递交物品或现场对白。镜头、手机和账号只是承载方式，不能
成为故事解决方案。

## 商业对象

商业对象只允许 `absent` 或 `causal`。可替换的象征、纪念或顺手露出一律删除；若选择 `causal`，
必须指出替换后断裂的具体因果边。商业连接只在故事完成后进入 `business_bridge`。

最后把触发、失败反馈、换招、互斥选择、主人公代价和目标结果压成一个清楚的句子。只保留一个
主要情绪机关，删除重复煽情。完成统一故事合同后停止。
